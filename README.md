# 风钩 · YiboWindowHome

使用 C++20 + Win32 实现的 Windows 窗口位置工具。当前版本为 0.9.0。

## 运行

运行 `dist/YiboWindowHome.exe`，在前台普通窗口的最小化按钮左侧显示操作按钮：

- 右键：更新默认记录的位置、尺寸和最大化状态。
- Ctrl + 右键：新增一条独立位置记录；已有启用记录保持不变，首次记录时自动启用新记录。
- 左键：恢复当前启用的记录；同一应用、同一规则范围的多个实例共享记录列表和单条启用选择。
- 中键：切换当前窗口置顶。
- 托盘右键：打开设置、暂停/恢复、退出；双击托盘打开设置。

双击托盘进入设置：左侧搜索、选择“全局默认”或应用，右侧有三个并列标签页：

- **窗口位置记录**：按当前显示器的实际数量和排列预览位置，管理默认与命名记录；选中只切换示意，启用并保存后用于左键恢复。可新增当前位置、编辑名称或删除记录，窗口规则的记录范围可单独选择。
- **按钮位置调整**：标题栏示意与实际按钮预览；普通/最大化窗口分别选择继承或自定义，显示实际生效的 X/Y 偏移。
- **窗口规则（高级）**：按窗口类型设置独立记录或排除临时对话框，保留规则优先级、标题条件及独立偏移。

应用重命名、更新程序路径和移除入口位于右上角更多菜单；启用开关与“保存更改”固定在顶部。列表、桌面示意随窗口尺寸伸缩，两侧操作说明和编辑操作贴近底部。水平 X 范围 -500 至 0（DIP），负数向左、0 与最小化按钮贴合；正值会遮挡系统按钮，界面会提示而不应用。垂直 Y 范围 -500 至 500，负数向上、正数向下。

“预览普通”和“预览最大化”分别临时切换到对应状态，演示 5 秒后恢复原状态、原尺寸与位置；预览期间三键暂停，不写入记录。“恢复继承”可重置，更改点击“保存”才写入。数据位于 `%APPDATA%\YiboWindowHome\prototype-state.json`，与正式版规划的 `state.json` 隔离。

按钮移动/缩放时复用已测量的尺寸快速跟随，停下后精确复核；切换窗口会短时重试首次识别。DPI、最大化状态和框架变化触发重新测量，空闲时保持低频校验。

添加应用支持按住“选窗口”拖到目标（Esc 取消）、拖入 exe/快捷方式、浏览选择；窗口选择会先展示身份和类名，供选择“整个应用”或“该窗口类型”，不自动把当前标题作为规则。已有应用会定位到原条目，首次右键记录也会自动加入名单。

“窗口规则”使用类名精确匹配，可选标题包含/等于条件，类名和标题区分大小写。规则可上移、下移、停用，也可排除此类窗口。优先级：应用禁用 → 任一排除规则 → 列表中第一条匹配的启用规则 → 应用默认 → 全局默认。每条启用规则拥有独立位置记录；禁用或停用保留已有记录。规则页只预览实际命中当前规则的窗口；排除/停用规则不提供按钮偏移预览。清除记录、移除规则或应用会分别确认。更新应用程序路径保留内部 ID 与记录；可读取打包应用 AUMID 时优先按该身份匹配。

每次右键记录同时保存全部活动屏幕的设备身份、排列、工作区及 DPI。同一显示环境精确恢复原坐标和跨屏布局；屏幕环境变化时在原屏幕按相对位置及 DIP 尺寸换算，原屏幕断开则回退到目标窗口当前屏幕。恢复会检查标题栏是否可操作，并区分精确恢复、环境换算及应用尺寸限制。

原型格式 1/2/3 的记录仍可读取，已有位置作为默认记录；下次成功保存升级为格式 4，并将上一份原文保留为 `.bak`。格式 4 保存命名位置及每个范围的单条启用选择。旧记录需重新右键记录，才能补齐完整屏幕信息。恢复与环境换算不会覆盖保存的位置。设备路径在换接口、扩展坞或镜像模式下可能变化或不可获取，此时采用保守回退。

多记录与预览底层接口见 [多位置记录与桌面预览](docs/多位置记录与桌面预览.md)。桌面预览按当前接入的显示器数量、排列、工作区和 DPI 生成画布坐标，并使用与实际恢复相同的位置规划；设置打开期间响应布局变化并定期复核。按钮位置预览和桌面位置实际预览结束后均恢复原窗口状态，预览期间暂停风钩鼠标操作。

按钮与当前窗口控制按钮行等高、上下沿对齐，宽度匹配当前最小化按钮，默认零间隙。Chrome、Codex 等 Chromium 窗口测量右侧最小化、最大化、关闭图标的间距与中心线；红果/Androws 使用四图标布局及内容区边界测量。最大化时排除屏幕外的不可见边框。其他窗口优先读取系统按钮和有效 DWM 边界，未知应用可使用系统回退尺寸。移动只平移按钮，尺寸或 DPI 改变后重测。默认 Y 偏移为 0，手动 Y 偏移会覆盖对齐位置。

默认按钮间隙为 0。背景图案、图标颜色和线宽取自当前最小化按钮，图标以单色细线表达回位功能。悬停进入/离开即时反馈；在原有最小化按钮上悬停约 2 秒可读取该应用的真实悬停样式，之后复用该样本。首次尚无样本时使用临时反馈，主题变化后重新采样。

红果及 Chromium 适配仅在窗口前台时采样标题栏右侧，在内存中识别，不保存图像。有效测量随窗口平移，尺寸或 DPI 改变后重测；尚无有效测量时等待重新识别。样式采样拒绝任何部分被遮挡的按钮区域；提示显示在整行控制按钮下方。尺寸、DPI 或主题改变后重新校准悬停样式。

原型需要 Windows 10/11 x64；当前实测环境为 Windows 11 22631。完整多屏兼容性仍在验证中。

## 构建和验证

安装带“使用 C++ 的桌面开发”、Windows SDK 和 CMake 的 Visual Studio。PowerShell 执行：

```powershell
.\scripts\build.ps1
```

脚本构建 x64 Release、复制运行文件至 `dist`，并运行独立进程集成测试。测试窗口可能短暂出现；持久化测试使用构建目录中的独立数据。运行文件采用 `/MT` 静态链接，依赖系统 DLL。

构建前先从托盘退出正在运行的风钩，避免运行文件被占用或两个跟随器互相干扰。构建流程包括几何、样式、用户截图、多屏规划及记录升级检查；多屏规划中的拔插、排列和 DPI 变化为模拟场景，实际双屏窗口移动由集成测试覆盖。

桌面交互测试需要测试窗口获得前台焦点；焦点不可用时会报告失败并停止消息操作，避免触及其他应用。按钮的置顶悬浮层只在目标前台时显示，中键独立控制目标窗口的置顶状态。

只构建并验证非 UI 核心、存储、规则、原生 API 与资源检查时，执行 `cmake --build build --config Release` 和 `ctest --test-dir build -C Release -V -LE ui`，不会安装到 `dist`。当前证据与待配合的实机测试见 [非 UI 测试验收](docs/非UI测试验收.md)。

可选开发入口：

```powershell
.\dist\YiboWindowHome.exe --settings
.\dist\YiboWindowHome.exe --fixture
.\dist\YiboWindowHome.exe --self-test "E:\path\to\isolated-test-data"
.\scripts\measure.ps1 -ProcessId 1234 -Label idle -Seconds 20
```

测试目录必须为专用中间数据目录；测试会构造正常及损坏状态文件。自动化测试不替代真实鼠标、管理员窗口、混合 DPI 和热插拔验收。

详见 [需求与实现方案](docs/YiboWindowHome-需求与实现方案.md) 和 [技术原型验证](docs/技术原型验证.md)。
