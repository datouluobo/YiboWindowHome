# 实机显示测试

显示设置和物理拔插由用户准备好后操作，测试程序使用自建的非激活窗口、独立目录及 JSON 报告收集证据。产品 UI 和 dist 不在该流程内。普通、最大化、跨屏矩形分别使用独立会话目录。

## 工具与结果

先构建测试目标：

```powershell
cmake --build build --config Release --target ManualDisplayTests
```

`scripts/test-display.ps1` 参数：

| 参数 | 含义 |
| --- | --- |
| Phase | Capture、Baseline、Changed、MixedDpi、NegativeLayout、Disconnected、Reconnected、Resolution |
| Session | 独立测试目录，内部保存 display-record.json 与逐步 JSON 报告 |
| ScreenIndex | 当前报告 Displays 数组的零基索引；Capture 表示记录来源，其他阶段表示恢复前测试窗口所在屏幕 |
| WindowState | Capture 时选择 normal、maximized、spanning；spanning-biased 用于偏向指定屏幕的非等面积跨屏窗口 |

每次命令创建并关闭测试窗口。报告包含当前屏幕身份、物理边界、工作区、DPI、请求矩形、实际矩形、普通还原边界、返回状态及源记录完整性。原始捕获文件保存完整旧拓扑，与每步报告一起复核。测试窗口处理 WM_DPICHANGED 的建议矩形，可用于验证实际跨 DPI 恢复。

| 退出码 | 判定 |
| --- | --- |
| 0 | 该阶段通过，或 Capture 成功 |
| 1 | 已执行测试，实际结果不符合预期 |
| 2 | 参数、捕获文件或工具运行错误 |
| 3 | 前置条件未满足，未完成该实机测试 |

RestoreAttempted 为 false 时不作产品恢复判定，RestoreStatus 为 null。实际恢复状态 0 为精确恢复、1 为环境适配、2 为应用限制、3 为失败；本工具的普通测试窗口应满足预期精确或适配结果，不把受限当作精确通过。

## 准备基线

下面假定副屏索引 1，主屏索引 0，按实际 Displays 数组确认。示例使用相对工作目录中的 build，数据与用户现有位置记录隔离。

```powershell
$mixedCase = Join-Path $PWD 'build\manual-display\mixed-normal'
.\scripts\test-display.ps1 -Phase Capture -Session $mixedCase -ScreenIndex 1 -WindowState normal
.\scripts\test-display.ps1 -Phase Baseline -Session $mixedCase -ScreenIndex 0
```

确认 Capture 与 Baseline 均成功后改变真实显示环境。同一案例恢复期间保留最初捕获文件，后续阶段只读它；需要新案例时建立新的 Session。

## 混合 DPI

将两屏设置为 100% 与 150% 或 200%，在另一缩放屏幕上初始化目标，再恢复到记录锚定屏幕：

```powershell
.\scripts\test-display.ps1 -Phase MixedDpi -Session $mixedCase -ScreenIndex 0
```

工具要求当前存在 96 DPI 与 144/192 DPI，并且目标实际从其中一屏跨到另一屏；相同 DPI、同一屏恢复或未检测到环境变化均返回 3。检查 ActualDpi、BeforeDpi、PlannedNormal、ActualBounds/OrdinaryAfterRestore 与 RecordFileUnchanged。

窗口实际 DPI 另与 LastNotifiedDpi、DpiChangeCount 核对。SavedDpiBasis 为 anchor-monitor；跨屏大窗口自身的 DPI 可能保留来源屏幕值，不应与保存的锚定显示器 DPI 混同。测试同时保留 NativeMonitorDpi 和 EqualOverlapTie，物理边界始终严格检查。实测结果见 [100%／150%](实机混合DPI-100-150.md) 与 [100%／200%](实机混合DPI-100-200.md)。

普通满工作区案例使用新的目录和 WindowState workarea，用于验证大窗口仍实际切换目的 DPI。最大化案例使用新的目录和 WindowState maximized。spanning 案例的锚定屏幕由实际最大重叠确定；依据捕获身份选择恢复前的另一缩放屏幕。准备好环境后由 Agent 读取拓扑并选择目标索引，无需用户操作测试窗口。

## 负坐标与排列

先将副屏上的普通或最大化测试窗口记录到新 Session，再将该副屏安排到主屏左侧或上方。执行 NegativeLayout，并把 ScreenIndex 指向恢复前目标所在屏幕。

该阶段要求保存的物理锚点仍存在，且恢复目的屏幕确实具有负坐标；仅其他屏幕位于负坐标、目标原屏已移除或未发生变化，都不能通过此阶段。一般排列或主屏变更可额外使用 Changed，检查稳定物理身份、相对位置与原记录不变。

## 拔插与接回

在待拔的副屏上记录一个新案例：

```powershell
$hotplugCase = Join-Path $PWD 'build\manual-display\hotplug-normal'
.\scripts\test-display.ps1 -Phase Capture -Session $hotplugCase -ScreenIndex 1 -WindowState normal
```

用户拔掉副屏后：

```powershell
.\scripts\test-display.ps1 -Phase Disconnected -Session $hotplugCase -ScreenIndex 0
```

必须减少活动视图，且原保存屏幕缺失，使 Fallback 为 true。成功后写入与原捕获绑定的 disconnected.checkpoint。工具观察的是 Windows 报告的活动视图；是否实际拔线由用户确认，不把软件模拟视图变化当作物理拔插证据。

接回并恢复原来的排列、分辨率及缩放后：

```powershell
.\scripts\test-display.ps1 -Phase Reconnected -Session $hotplugCase -ScreenIndex 0
```

Reconnected 要求此前成功完成匹配的断开阶段，并且当前拓扑回到原环境，才能核验原矩形精确恢复。缺失或过期的检查点、原记录变化、未恢复原拓扑均返回 3。环境仍有变化时可另用 Changed 检查适配，但不能计为“接回原环境后精确恢复”。

## 分辨率与工作区

新案例捕获后，改变保存屏幕的分辨率或任务栏工作区，执行 Resolution。工具核对原物理屏幕仍存在，并要求该屏幕的分辨率尺寸或工作区相对边距实际改变。仅改屏幕位置或缩放、或断开原屏后回退，不能冒充此项通过。检查恢复矩形、DPI 与可操作性；恢复原显示设置后可执行 Baseline 再核对原位置。

## 证据与覆盖范围

每个阶段自动在 Session 中保存带时间名的 JSON。Capture/恢复不会操作用户窗口，也不会改写正式原型配置。电脑实际重启、打包应用升级、不同权限目标和完整常驻资源采样仍需按 [非 UI 测试验收](非UI测试验收.md) 的剩余项目执行；工具的退出码和报告不代替这些独立验收。

工具自身的自检包含正常/最大化/跨屏基线、捕获保护、记录不变，以及对未变化桌面、伪造检查点和缺失捕获的拒绝。自检通过只证明工具可用，不能记作真实混合 DPI、排列变化或拔插通过。
