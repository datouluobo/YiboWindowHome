# 多位置记录与桌面预览

2026-10-29 功能补充，替换原方案中“每个范围始终只有一份最新记录”的约定。

## 记录与操作

- 应用默认范围和每条窗口规则各有独立的位置列表；同范围的程序实例共享列表。
- 默认记录键沿用 `应用ID/default` 或 `应用ID/规则ID`。新增记录键为 `范围/p-稳定ID`，名称可修改，ID 和几何数据不随改名改变。
- 每个范围只启用一条记录。右键始终更新该范围的默认记录；Ctrl + 右键追加记录；左键恢复该范围启用的记录；中键切换当前窗口置顶。
- 新增记录不切换已有的有效启用记录。范围中还没有有效记录时，新记录自动启用。默认记录槽始终存在，尚未记录时其数据为空。
- 删除启用的自定义记录后优先回到默认记录；若默认记录没有数据，则启用另一条已有记录。清除默认记录内容保留其他记录；移除规则清理该范围全部记录及启用选择。
- 每个范围最多 128 个槽（含默认槽），全局最多 4096 份记录，沿用 4 MiB 文件上限。超过限制或写入失败时，不替换当前有效状态。
- Ctrl 修饰键在按下时与目标窗口、规则范围一起绑定。取消捕获、目标失效或范围变化时不提交操作。

## 存储与接口

格式 4 在每份记录中增加 `name`，并增加 `activeRecords`（范围到记录键）列表。格式 1/2/3 保持可读，旧记录作为默认记录；读取不改写文件，下一次成功保存升级并备份旧文件原文。新增名称、启用选择和位置几何在同一原子事务中保存。

`positionEntries` 返回默认槽及所有命名记录；`activePositionKey` / `activePositionRecord` 查询当前启用记录。`savePositionRecord`、`activatePositionRecord`、`renamePositionRecord`、`erasePositionRecord`、`erasePositionScope` 编辑草稿，调用方须先成功 `Store::save` 再替换运行态。

设置保存合并运行期间新增的记录和启用选择，保留原有并发删除冲突提示。更新默认记录不会覆盖命名记录或隐式切换其启用状态。

## 两种预览

1. 按钮位置预览：`PreviewPlacement::begin` 临时切换普通/最大化窗口状态，配合现有草稿偏移显示风钩按钮，结束恢复窗口原放置状态。
2. 桌面位置预览：`buildDesktopPreview` 将当前显示器布局与指定记录投影到画布；`currentDesktopPreview` 每次重新枚举接入的显示器。纯计算预览不移动目标、不覆盖记录。`PreviewPlacement::beginDesktop` 提供实际移动目标的临时预览，结束调用 `restore` 或析构后恢复原放置信息。

画布保留每块当前显示器的真实位置、相对尺寸、主屏标记、工作区和 DPI。支持单屏、多屏、竖屏、负坐标及上下排列，采用同一比例缩放整个物理桌面。没有显示器或画布无效时返回失败。镜像模式按 Windows 提供的逻辑桌面视图展示，不虚构扩展桌面。

记录位置使用 `planRestore` 与实际恢复共用规划，包括设备身份、显示器断开后的回退、DPI 换算、任务栏工作区与可达标题栏修正。最大化记录在画布上显示当前目标屏工作区。返回规划标记供前端解释环境变化与回退；尚无记录时仍可显示当前屏幕布局。

前端在打开预览、切换记录、调整画布尺寸以及收到显示器布局/DPI/工作区变化通知时重新请求模型。纯示意不等同于目标应用实际接受几何结果，应用最小尺寸等限制由实际恢复状态反馈。

## 已确认界面结构

- 左侧应用名单、搜索、操作说明、选窗口和浏览添加入口。
- 右侧三个并列标签页：窗口位置记录、按钮位置调整、窗口规则（高级）。每页仅显示对应内容；保存操作位于右上。
- 位置记录页显示当前接入显示器布局及记录列表，区分“默认”与“启用中”。按钮调整页显示标题栏相对位置及普通/最大化偏移。
- 左右底部随窗口可用高度安排；列表与预览区承担弹性空间，底部操作和说明贴合内容，不保留无用途的底部空白。
- 设置界面已接入三标签页、多记录编辑、单条启用、两类预览与实时显示器布局；记录查看和启用操作分开。列表与预览分配剩余空间，底部编辑操作与左侧添加入口保持贴底。

## 本次验证

- x64 Release 完整构建通过。
- CTest 中除 `prototype`、`core_soak` 外的 15 项检查全部通过，涵盖多记录、旧格式升级、显示器规划/画布、设置合并、临时桌面预览、存储故障与容量、规则属性及原生窗口 API。
- 多记录检查覆盖命名、单条启用、右键更新默认而保留其他记录、规则范围隔离、删除回退、无效引用与数量上限。当前实际显示器布局由只读枚举检查覆盖；拔插、竖屏和负坐标排列另有模拟规划检查。
- 主程序 `prototype` 要求管理员权限，CTest 直接启动受限；按项目脚本的进程启动方式运行后，前台焦点不稳定导致交互检查失败。Ctrl + 右键等鼠标消息完整链路仍需在稳定前台环境复验，不能据此宣称完整实机交互通过。
- 测试在初次记录前置条件失效时会清理专用窗口并返回失败，不继续读取未建立的应用条目。长期 soak 本次未重跑。

三标签页 UI 接入后，Release 及同一组 15 项回归再次通过。原生设置检查增加了三页互斥显示、记录启用/改名事务、查看与启用分离、搜索映射、底部控件顺序和 30 次资源释放检查。默认与紧凑两种排版已目视对照，详见项目根目录 `design-qa.md`。
