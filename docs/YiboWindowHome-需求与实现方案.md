## 1. 产品目标

项目中文名：**风钩**。英文项目名：**YiboWindowHome**。

开发一个轻量 Windows 桌面常驻工具，在其他程序窗口右上角、最小化按钮左侧显示一个操作按钮：右键记录窗口位置与尺寸，左键恢复，中键切换置顶。

位置记录必须持久化。目标程序关闭再打开、本工具退出再打开、电脑重启后，都应能够找到原记录并恢复。支持多显示器、混合 DPI 缩放及显示环境变化。

同一程序的多个相同窗口共享一份位置记录。任一窗口记录都会覆盖这份记录；恢复和置顶只作用于被点击按钮对应的当前窗口。

通过一个通用“应用名单”统一管理程序身份、启用状态、按钮微调和可选窗口规则。禁用应用或窗口规则即实现黑名单。

### 2.2 建议默认行为

- 未配置的普通应用使用全局默认规则并显示按钮，用户无需逐个添加才能使用。
- 首次右键保存时，自动建立应用条目，便于后续微调和禁用。
- 第一版以当前前台目标窗口显示一个按钮为基础；点击按钮过程中保持原目标绑定。减少遮挡和多个悬浮层的维护复杂度。
- 手动左键触发恢复；启动应用时自动恢复作为后续扩展。
- 置顶状态在当前窗口生命周期内有效，重启后不主动重新置顶。
- 开机自启动提供设置开关，默认关闭。
- 风钩启动时请求管理员权限，以便统一操作普通权限和管理员权限窗口；若系统要求授权，由用户通过 Windows 授权流程确认。开机自启动及其权限配置仍在设置功能完成后实现并测试。
- 权限提升后，普通权限的资源管理器向风钩直接拖入文件可能受到 Windows 限制；应用添加仍须提供浏览和选窗口入口，拖放兼容性待 UI 验收。依据：[Microsoft COM elevation 文档](https://learn.microsoft.com/en-us/windows/win32/com/the-com-elevation-moniker)。
- 第一版按当前显示模式运行；独占全屏、系统安全桌面等不作为支持目标。

## 3. 按钮与交互

### 3.1 外观与位置

默认呈现：`窗口标题…… [本工具按钮] [最小化] [最大化/还原] [关闭]`。

采用独立、无边框的小型悬浮窗口。按钮高度与当前窗口控制按钮行一致，上下沿及图标中心线与其对齐；宽度独立取当前窗口最小化按钮的实际宽度。按钮锚定在最小化按钮左侧，默认右沿与最小化按钮左沿接触，水平间隔为 0。测量区域不包含窗口阴影及外侧不可见调整尺寸边框；最大化时将可视边界裁到所在屏幕工作区。

宽度优先读取有效的最小化按钮边界；无法读取时，可用有效的 DWM 三按钮组边界推算单个按钮宽度及左侧锚点。应用适配器可提供进一步测量：红果所属的 Androws 自绘窗口在前台时，仅采样已识别标题栏右侧区域，根据最小化横线及其右侧最大化、关闭、侧栏图标的等距排列测量按钮单元宽度和锚点。该结果标记为实测标题栏来源。

红果适配器最多每秒采样一次，图像只在内存中短暂处理；缓存按窗口、进程、标题栏尺寸和 DPI 校验，窗口移动时将测量结果平移，尺寸或 DPI 改变时重新测量。采样失败时复用同一几何状态下的有效测量；尚无有效结果时暂缓显示并重测。其他尚无适配器的未知应用仍可使用 46 DIP 的通用回退宽度。诊断保留宽度来源。

标题栏几何信息按以下优先级获取：

对于 Chrome、Codex 等 Chromium 自绘窗口，优先从实际最小化、最大化、关闭图标的等距排列测量宽度、锚点和控制行高度，覆盖不可靠的系统高度或 DWM 组宽估算。检测同时校验关闭图标形状、间距与右侧留白；单次采样最多右侧 360 DIP × 顶部 56 DIP，每秒至多一次。缓存按窗口、进程、尺寸和 DPI 校验，尚无有效测量时等待重新识别。控制行可能低于整个标题内容区，不能直接用内容区高度代替。

1. 标准标题栏：使用系统返回的有效最小化按钮上下边界，与相邻控制按钮对齐。
2. 自绘标题栏：可识别宽幅子内容窗口时，以其顶部作为标题栏底部，配合可视窗口/客户区顶部确定真实高度。
3. 非客户区：客户区起点能明确区分标题栏时，以可视顶部至客户区起点作为标题栏范围。
4. 无法可靠识别时：使用当前 DPI 的系统标题栏高度作为稳定回退值；此值属于估计，后续可通过应用适配规则校准。

移动窗口只平移按钮；普通宽度和高度变化只更新锚点，不能改变由同一标题栏测量得到的按钮尺寸。最大化/还原、实际标题栏布局或目标屏幕 DPI 改变时重新测量。所有几何统一使用物理屏幕坐标。默认垂直偏移为 0；用户明确设置的 Y 偏移作为对齐位置的手动覆盖，不改变按钮高度。

悬浮按钮会覆盖所在区域，不会替目标程序重新排列标题栏内容。自绘标题栏通过应用偏移避让标签页、搜索框和应用自带按钮。

普通与最大化状态各保留一组偏移；初始共用，用户可选择分别调整。偏移以 DIP 保存，显示时按目标屏幕 DPI 换算，避免跨屏后视觉偏移量失真。

设置中明确展示“继承全局/应用”或“自定义按钮偏移”；继承模式展示实际继承值，避免残留自定义数值造成误解。水平 X 输入范围 -500 至 0（负数向左），正向输入须提示无法应用，不能静默裁成 0；垂直 Y 为 -500 至 500（负上正下）。允许数字输入过程中暂时为空或仅为负号，焦点/刷新通知不触发表单提交；点击保存、预览等明确操作时再校验。

普通、最大化分别提供预览入口，预览时临时切换目标到对应状态，结束或取消后恢复原窗口放置信息；不持久化临时窗口变化。现有旧格式数值仍兼容读取，保留已保存的配置与位置记录。

按钮宽度与高度分别依据最小化按钮和标题栏测量结果决定；间隔和回退锚点使用集中规则。微调必须允许用户移动到可用区域；安全检查优先防止覆盖系统控制按钮，不能因标题栏安全区域识别错误而让偏移完全失效。

### 3.1.1 背景、图标与交互状态

普通背景复用相邻最小化按钮的局部背景图案，去除其图标后用于绘制风钩按钮，保留渐变和边缘细节。回位图标保留功能含义，使用与原按钮一致的前景颜色、图标尺度与线宽；置顶、成功和失败反馈同样采用该单色细线风格。

悬停进入和离开即时重绘；按下状态与鼠标捕获、释放或取消同步。用户悬停在原最小化按钮时，自动读取并缓存其真实悬停背景和前景色，随后风钩按钮使用该状态图案。首次尚未观测到原生悬停时，采用基于当前背景和前景色推导的临时反馈；这是待校准状态，不能宣称已与任意自绘应用逐像素一致。按下状态同理，观测到实际状态后优先使用真实样本。

样本只取控制按钮区域、仅在目标前台且整个采样区域未被其他窗口遮挡时读取，不保存图像文件；不能只检查中心点而把提示框等覆盖物复制到背景。每个窗口独立缓存，最多保留 8 个窗口；每个状态背景最多 128×96 像素。主题底色、前景色、按钮尺寸或 DPI 变化时，重新校准悬停/按下样本。提示框定位在整个控制行下方并与其保持 4 DIP 间距。手动偏移仍作为明确的位置覆盖，默认偏移为 0。

### 3.2 鼠标行为

| 操作 | 结果 |
| --- | --- |
| 右键释放 | 采集当前目标窗口，保存共享记录；落盘成功后短暂显示“已记录” |
| 左键释放 | 查找记录并恢复当前窗口；无记录时提示“先右键记录位置” |
| 中键释放 | 切换当前窗口置顶/取消置顶，图标同步变化 |
| 悬停 | 提示“左键恢复 · 右键记录 · 中键置顶”，可附记录状态 |

右键由本工具消费，不弹出目标标题栏的系统菜单。点击按钮应保持原目标窗口和键盘焦点，不能因悬浮层成为前台窗口而操作错误对象。按下和释放属于同一次操作，只执行一次，不额外实现双击动作。

应用列表编辑与按钮微调通过托盘设置进入，避免与上述鼠标动作冲突。

### 3.3 生命周期与遮挡

- 目标隐藏、最小化、销毁、切换至其他前台应用或不在当前可见桌面时，隐藏按钮。
- 窗口移动、缩放、最大化/还原、DPI 变化后更新按钮位置。
- 弹出菜单、模态窗口或其他窗口覆盖按钮区域时，按钮不得穿透遮挡显示在最上层。
- 工具暂停时隐藏按钮并停止操作；已有位置记录继续保存。
- 目标窗口失效或被替换后，取消当前点击；每次执行前重新校验目标身份。

## 4. 通用应用名单

### 4.1 设置结构

建议采用左侧“全局默认＋应用列表”、右侧所选条目详情的结构。列表显示程序图标、名称、启用状态、是否有记录；详情显示身份、偏移、位置记录摘要和窗口规则。

应用条目字段：

| 字段 | 说明 |
| --- | --- |
| 应用 ID | 工具分配的稳定内部 ID，记录引用该 ID |
| 显示名称、图标 | 面向用户，可编辑名称；图标可按需读取并缓存 |
| 应用身份 | 普通桌面软件以规范化完整 exe 路径识别；打包应用使用 AUMID。若顶层 HWND 由 ApplicationFrameHost 承载，则从对应 CoreWindow 子窗口解析实际包身份 |
| 是否启用 | 禁用该应用的所有目标窗口 |
| 普通/最大化偏移 | X/Y，继承全局或使用应用自定义值 |
| 窗口规则 | 可选，用于区分窗口类型或排除局部窗口 |
| 位置记录摘要 | 保存时间、尺寸、显示器、状态 |

### 4.2 三种添加方式

1. **准星选窗口**：按住拖动准星，实时框选命中的顶层窗口；松开显示程序名称、路径、窗口类名与当前标题，供选择“整个应用”或“该窗口类型”。当前标题作为识别参考，默认不自动生成标题条件。
2. **拖入文件**：接收 exe 或 `.lnk`；解析快捷方式的实际目标。不能解析为支持的应用身份时说明原因。
3. **浏览选择**：选择 exe 或快捷方式，经过同样的解析与去重流程。

命中已存在应用时定位到该条目，允许添加窗口规则。取消添加不修改配置。选窗口工具不能选中本工具自己的界面、桌面或任务栏。

管理员窗口和受保护程序的信息读取、拖放可能受权限限制，失败时提供清楚反馈，并保留准星/文件选择等其他可用入口。

### 4.3 窗口规则与优先级

第一版窗口规则支持窗口类名精确匹配，可选叠加标题“包含”或“等于”条件。多个条件同时满足才命中。标题随文档和标签页变化，默认不使用完整标题作为持久化身份。

规则应用顺序：

1. 系统级安全过滤：本工具、桌面、任务栏、隐藏窗口等不作为目标。
2. 应用禁用：整应用禁用优先，窗口规则不能重新启用。
3. 局部禁用：任一禁用窗口规则命中，当前窗口不显示按钮。
4. 启用窗口规则：从命中规则中选取优先级最高的一条，获得独立记录范围和偏移覆盖。
5. 应用默认：没有命中窗口规则时使用应用默认记录和偏移。
6. 全局默认：未配置应用使用全局设置。

启用窗口规则可调整顺序；优先级相同时按保存的稳定顺序决定，并在设置中显示最终命中规则。工具窗口、临时对话框等默认过滤；用户明确建立的窗口规则可允许适合操作的此类顶层窗口。

禁用只影响按钮与操作，保留原记录。移除应用配置、清除记录属于不同操作：清除记录只清除选定范围；移除条目前展示关联数据范围并确认。

## 5. 共享记录与持久化

### 5.1 记录范围

记录键为：`应用内部 ID + 记录范围 ID`。

- 默认记录范围为“应用默认”，同一应用落入该范围的窗口共享一份记录。
- 用户建立明确的窗口类型规则后，该规则拥有独立的记录范围；命中同一规则的窗口仍共享一份记录。
- 每个记录范围始终只有一份最新记录，右键成功保存后覆盖。
- 不按进程 ID、窗口句柄、窗口创建顺序或运行实例分配长期记录。
- 左键恢复仅操作当前窗口，不批量移动同应用其他窗口；中键置顶同样如此。

例如：两个浏览器普通窗口共用默认记录。在 A 窗口记录位置，再点击 B 的恢复按钮，B 移动到该位置，A 保持不变。重启浏览器后，新窗口继续使用此记录。

### 5.2 每份位置记录

| 数据 | 用途 |
| --- | --- |
| 应用 ID、范围 ID、保存时间 | 查询及展示 |
| 普通窗口边界 | 恢复普通状态的位置与外部尺寸 |
| 保存时状态 | 普通或最大化 |
| 保存时实际边界 | 同环境恢复、跨屏情况分析 |
| 原锚定显示器身份 | 找回原显示器 |
| 显示器边界、工作区、DPI | 换算及任务栏变化处理 |
| 全部活动显示器布局摘要 | 判断是否为相同显示环境 |
| 相对位置与 DIP 尺寸 | 环境变化时恢复依据 |

普通边界以统一物理屏幕坐标归档；同时保留恢复所需的窗口放置信息。必须明确区分 Win32 工作区坐标、屏幕坐标、DIP 和可见边框，不能混用。

记录中的尺寸换算 DPI 以锚定显示器为基准；窗口自身的 `GetDpiForWindow` 与最后收到的 `WM_DPICHANGED` 是另一组数据。跨屏窗口可能保留来源屏幕的窗口 DPI，两者不应混为一谈。相同拓扑下的跨屏恢复严格核对原物理矩形，并核对窗口 DPI 与系统通知一致；单屏及最大化窗口另核对目标屏幕 DPI，不能仅因跨屏窗口 DPI 与某一相交屏幕不同就判定几何恢复失败。

右键记录最大化窗口时，保存“最大化状态＋背后的普通恢复边界”；恢复时先建立正确的普通边界及目标显示器，再最大化。用户无法通过隐藏的按钮记录最小化窗口，记录状态也不持久化为最小化。

### 5.3 应用重新匹配

普通应用路径按 Windows 路径规则规范化、大小写不敏感匹配；相同文件名但不同路径默认视为不同应用。快捷方式参数不自动创建新的身份范围。

软件升级导致 exe 路径改变时，允许用户更新原条目的路径并保留内部 ID 和记录；不得只因 exe 同名就自动合并。打包应用优先使用不依赖版本安装目录的 AUMID。对于 `ApplicationFrameWindow` 宿主窗口，应从其 `Windows.UI.Core.CoreWindow` 子窗口取得应用进程身份，不能把 `ApplicationFrameHost.exe` 当作具体应用的唯一身份；仍无法读取时提示适配限制。

### 5.4 存储可靠性

建议在 `%APPDATA%\YiboWindowHome\state.json` 保存应用名单、规则、记录和 schemaVersion。该文件按一份完整状态事务写入，避免名单与记录分别成功导致不一致。

保存流程：采集并验证 → 串行化更新 → 写同目录临时文件并刷新 → 原子替换正式文件 → 保留上一份有效备份 → 显示成功。首次保存使用适合的原子提交方式。失败时保留正式文件、回滚本次内存变更并提示，不能出现成功反馈。

启动时验证结构和版本；正式文件损坏时尝试备份并告知用户。两份都无效时保留故障文件，提示恢复/导入，不静默覆盖用户数据。对未来版本文件拒绝自动降级改写。

配置导出包含应用名单、偏移及位置记录。导入先验证并展示摘要，第一版采用确认后整体替换，替换前备份当前状态。

## 6. 多显示器恢复规则

### 6.1 基础约定

- 使用整个虚拟桌面的坐标，允许负 X/Y，不能把负数当作越界。
- 显示器工作区扣除任务栏等保留区域。
- 显示器身份尽量组合设备路径、显示配置目标信息等识别；“显示器 1/2”和 DISPLAY 编号不能作为唯一长期身份。换接口、扩展坞、镜像等场景仍可能无法唯一匹配，需降级。
- 锚定显示器取与窗口相交面积最大的显示器；无相交时取最近显示器。跨屏窗口另保留完整桌面边界。
- 第一版每个记录范围保存最新一份位置；显示环境变化时根据这份记录计算恢复，不按显示环境自动创建多套位置档案。

### 6.2 恢复决策表

| 情况 | 恢复行为 |
| --- | --- |
| 显示器身份、排列、分辨率、工作区和 DPI 均一致 | 优先使用原物理坐标与尺寸；跨屏窗口保留原跨屏位置 |
| 原显示器存在，排列变化 | 在原显示器上按保存的相对位置恢复 |
| 原显示器存在，分辨率或工作区变化 | 按相对可移动空间映射位置，必要时缩小到可用范围 |
| 原显示器存在，DPI 变化 | 优先保持 DIP 尺寸的视觉一致性，再按新工作区定位 |
| 原显示器断开或无法可靠识别 | 使用当前目标窗口所在显示器；不可用时使用主显示器 |
| 原记录为最大化 | 在选定显示器建立普通恢复边界，再最大化 |
| 原跨屏布局发生变化 | 降级为锚定显示器内可操作布局，给出简短提示 |

### 6.3 环境变化时的位置换算

设保存时工作区为 `(L, T, W, H)`，普通窗口为 `(x, y, w, h)`。窗口可容纳时保存：

`rx = clamp((x - L) / max(1, W - w), 0, 1)`  
`ry = clamp((y - T) / max(1, H - h), 0, 1)`

保存逻辑尺寸：`wDip = w × 96 / dpiX`，`hDip = h × 96 / dpiY`。

环境变化后，先按新 DPI 计算尺寸，再限制到目标工作区允许的范围，最后按新的可移动空间计算：

`xNew = LNew + rx × max(0, WNew - wNew)`  
`yNew = TNew + ry × max(0, HNew - hNew)`

此规则保持“靠左、居中、靠右”等相对关系；相同环境仍走原始坐标恢复，避免量化误差破坏精确位置。

### 6.4 可操作性与限制

- 环境变化时优先让整个窗口进入目标工作区。
- 应用最小尺寸超过工作区时，尊重应用限制，至少保证标题栏和一段拖动区域位于真实显示器上，并提示无法完全容纳。
- 不使用所有显示器外接矩形判断可见性，因为显示器间可能有空隙。
- 同环境允许保留可操作的跨屏或部分离屏布局；若记录的标题栏完全无法操作，则作最小位置修正。
- 恢复后读取实际边界和状态。应用自行限制尺寸或重排时，如与目标有明显偏差，报告“已按应用限制调整”；不无限重试。
- 恢复期间发生 DPI 变化时，等待布局稳定后作一次有界校正。单屏目标若实际 DPI 仍属于来源屏幕，可在目的工作区内使用较小的中间矩形触发 DPI 切换，再恢复计划矩形；复核实际 DPI 和边界，受应用限制时返回 Limited。跨屏原矩形不强制切换到锚定屏幕 DPI。恢复窗口时保持原置顶状态，除非用户执行中键操作。
- 降级计算不覆盖原持久化记录，用户再次右键才更新记录。

### 7.1 事件与调用链

窗口事件优先驱动更新，配合有限的状态校验；避免高频扫描所有进程。跟踪处理需有超时和事件合并，防止无响应目标窗口拖慢工具。

移动/缩放事件走轻量几何路径，复用已测得的按钮宽高及标题栏边界，按窗口右上边缘同步位置；停止活动约 160 ms 后重新精确测量。首次切换窗口补充约 500 ms 的短时重试，位置事件期间使用 16 ms 定时校验请求，不将其当作端到端延迟保证。DPI、最大化状态、框架样式或窗口身份变化时重新测量，缺少可靠自绘按钮测量时继续识别，不能套用错误宽度。外观采样安排在按钮放置和绘制之后；空闲仍每秒校验，不常驻高频定时器。

右键：锁定目标 → 验证有效性与禁用规则 → 解析应用/范围 → 采集位置与显示环境 → 保存完整状态 → 成功反馈。

左键：锁定目标 → 匹配记录 → 获取当前显示环境 → 计算目标边界与状态 → 执行恢复 → 读取结果并有限校正 → 反馈。

中键：锁定目标 → 读取实际置顶状态 → 切换 → 核验并更新图标。

### 7.2 主要 Windows 能力

- 窗口枚举和身份：EnumWindows、GetWindowThreadProcessId、QueryFullProcessImageName、GetClassName 等。
- 标题栏定位：WM_GETTITLEBARINFOEX 等；自绘窗口使用默认锚点和用户偏移。
- 窗口事件：SetWinEventHook，优先进程外监听；补充显示器配置变化通知。
- 位置和状态：GetWindowPlacement / SetWindowPlacement、GetWindowRect / SetWindowPos；可见边框使用 DWM 信息作辅助。
- 多屏和缩放：显示器枚举、显示配置查询、工作区与 DPI 查询；本工具启用 Per-Monitor V2，并统一坐标转换。
- 置顶：SetWindowPos 的 HWND_TOPMOST / HWND_NOTOPMOST，保持尺寸和位置。

悬浮按钮使用独立、无宿主所有者、不激活的置顶工具窗口，仅在目标处于前台且按钮区域可操作时显示；切换应用、打开菜单、目标最小化或失效时立即隐藏或重新绑定。按钮自身的置顶属性与目标窗口置顶状态分开管理，不改变目标状态。遮挡检测区分真正覆盖标题栏的窗口与鼠标穿透的分层窗口。验收除检查窗口可见标志外，还必须验证按钮中心的实际鼠标命中对象。悬浮窗口的跟随 Z 序、非激活点击、弹窗遮挡和虚拟桌面切换必须通过原型验证。本机 YiboCodexHUD 项目可供研究边界计算、偏移和 DPI 转换行为；风钩使用原生 Win32 窗口实现。

## 8. 兼容性与失败行为

| 情况 | 预期处理 |
| --- | --- |
| 自绘标题栏无法识别系统按钮 | 使用默认锚点，允许应用微调 |
| 目标进程权限不足 | 提示原因和可行处理；不能静默报告成功 |
| 目标窗口卡死 | 查询有超时，按钮隐藏或提示，工具保持响应 |

## 9. 验收标准

### 9.1 核心与持久化

1. 普通窗口记录后，移动并缩放，再左键恢复，回到保存位置和外部尺寸；标准测试窗口在相同 DPI 下目标误差不超过 2 个物理像素。
2. 关闭目标应用再打开，能够恢复同一共享记录。
3. 完全退出本工具并重启，记录及应用偏移仍有效；电脑重启后再次验证。
4. 同程序两个相同窗口：A 保存，B 恢复；A 不随之移动；B 保存后 A 恢复到新记录。
5. 已配置独立窗口类型的主窗口与设置窗口，记录互不覆盖。
6. 中键切换只影响当前窗口，图标反映实际状态。
7. 最大化记录正确恢复到目标屏幕；随后手动还原，普通边界正确。
8. 模拟保存失败时不显示成功、不损坏旧记录；损坏正式文件时可从备份恢复。

### 9.2 名单和按钮

9. 三种添加方式识别同一应用时合并到同一条目；快捷方式可解析实际目标。
10. 应用偏移在重启后保持，普通与最大化配置按设定生效。
11. 整应用禁用与窗口类型禁用均有效，重新启用后原记录可用。
12. 自绘标题栏可通过微调避让已有内容；按钮不遮住最小化、最大化和关闭按钮。
13. 切换前台、最小化、打开模态弹窗、切换虚拟桌面时，按钮不残留在无关窗口上。
14. 点击悬浮按钮不误操作其他窗口，不改变正在输入的目标焦点。

### 9.3 多显示器

15. 副屏位于主屏左侧或上方，负坐标保存恢复正确。
16. 100% 与 150%/200% 混合缩放，跨屏后按钮大小和偏移合理，位置恢复符合 DPI 策略。
17. 调整主副屏排列后，优先回到原显示器的相对位置。
18. 拔掉原显示器后可在当前屏恢复；重新接回且未覆盖记录时仍可回到原位置。
19. 修改分辨率、任务栏工作区后，窗口保持可操作。
20. 相同环境下跨屏窗口精确恢复；布局改变后按锚定屏降级，并保留原记录。

验收覆盖标准 Win32 窗口、WPF/WinForms 窗口、浏览器或 Electron 自绘窗口、文件管理器、管理员窗口、固定尺寸对话框。对目标应用自身拒绝的操作记录明确限制，不把其计为精确恢复通过。

## 12. 技术原型验证

原型采用 C++20 + Win32，入口为 `src/main.cpp`，位置与存储逻辑位于 `src/state.cpp`，规则解析位于 `src/rules.cpp`，设置位于 `src/settings.cpp`，文件与快捷方式解析位于 `src/app_files.cpp`。功能包含托盘、非激活跟随按钮、三键操作、多屏恢复、应用名单、按应用偏移和窗口规则。记录按应用内部 ID 与规则范围共享。

原型使用 `%APPDATA%\YiboWindowHome\prototype-state.json` 和独立的 `prototypeSchema`，与正式版 `state.json` 隔离。当前按规范化 exe 路径识别普通应用。2026-10-27 已补充活动显示路径与监视器设备路径匹配、全活动屏幕布局比较、按相对位置与 DPI 换算、原屏幕缺失回退及可操作标题栏检查。只有记录与恢复操作采集屏幕布局，不增加后台轮询。

原型格式 3 在既有实际窗口边界、锚定屏幕设备路径和全屏幕布局上，加入应用名单、稳定应用/规则 ID、独立记录范围及保存时间。兼容格式 1/2：启动时在内存中建立对应应用和默认记录范围，不重写文件；下一次成功写入时升级并备份原文。旧位置记录在用户再次右键记录时补齐屏幕信息。编号与物理设备路径分开匹配；已知设备路径缺失或不唯一时不会仅凭 DISPLAY 编号绑定到另一块屏幕。对于原记录没有物理身份的旧版或镜像环境，设备名只能提供尽力匹配，不能保证接口更换后的身份连续性。

应用名单已接入三种添加入口、名称/路径编辑、启用、普通与最大化偏移和记录摘要。窗口规则支持类名、标题条件、排除、停用、稳定列表优先级及独立记录；编辑可预览 5 秒，到期返回，预览期间三键暂停。设置关闭销毁控件、字体、图标和预览状态；保存合并编辑期间新增的位置及自动加入的应用，不覆盖新记录。移除和清空操作明确展示关联范围并确认。标题与类名按大小写精确规则匹配，打包应用身份按系统返回的 AUMID 精确匹配，普通路径按 Windows 大小写不敏感规则匹配。
